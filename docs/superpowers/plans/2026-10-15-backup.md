# Homelab Backup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for native execution, or superpowers:subagent-driven-development if the user selects delegation. Implement task-by-task using the checkboxes below.

**Goal:** Back up the active homelab databases and configuration to encrypted B2 storage every six hours, with externally monitored success and a verified restore.

**Architecture:** A separate Ansible backup play provisions a root-only Python runner and systemd timers. Public inventory describes repositories and jobs; encrypted Vault supplies repository credentials and per-job Healthchecks URLs. Database adapters prepare consistent exports in a stable staging tree before restic uploads one complete batch.

**Tech Stack:** Ansible, systemd, Python standard library, restic, Docker CLI, PostgreSQL/MariaDB client tools inside their existing containers, SQLite backup API.

**Spec:** `docs/superpowers/specs/2026-10-15-backup-design.md` (user approved).

## Global Constraints

- Existing uncommitted lifecycle fixes remain intact. No commits, branch changes, deployments or production restores without user instruction.
- Do not print or persist decrypted production Vault content for tests. Fake credentials only in tests; production Vault remains encrypted and unchanged by implementation.
- Repository: `s3:https://s3.us-west-004.backblazeb2.com/homelab-db-snapshots/ereshkigal`; Application Key restricted to `ereshkigal/`.
- Public identifiers: `backup_repositories.database` and `backup_jobs.database`; scope includes both DB and config.
- Secrets: `vault_secrets.backup.repositories.database.{access_key_id,secret_access_key,restic_password}` and `vault_secrets.backup.jobs.database.healthchecks_ping_url`.
- Backup schedule: 00:00, 06:00, 12:00, 18:00 Asia/Taipei. Healthchecks Simple 6h period, 2h grace, Email notification.
- Retention: all snapshots within 48h, 14 daily, 8 weekly, 12 monthly. Backup and maintenance serialize via one repository lock outside the staging tree.
- Exclude media, downloads, caches, running DB data directories, retired New-API, LANraragi, and Home Assistant.
- No database upgrades, forced service restarts, whole-site deployment, bucket lifecycle changes, Object Lock, or automatic external account creation.
- Root directories 0700, secrets/staged files 0600; Ansible secret tasks no_log and diff false. Never send SQL or raw command output to Healthchecks.
- Controller repo/Vault backup and off-host key escrow are documented separately; do not claim server backup protects controller-only data.

## Review Focus

- A failed new export must never reuse a previous batch or emit a successful backup notification (Task 2 tests).
- Prefix-limited S3 access must include restic config, lock, index, snapshot and pack operations (Task 5 remote validation).
- SQLite WAL changes must survive export; media and symlinks must not escape the source allowlist (Task 2 tests).
- A maintenance invocation must never prune unrelated repositories/jobs or overlap a backup (Task 3 tests).
- Credentials and notification failures must not leak through process logs, Ansible output, or exception messages (Tasks 2–4 tests).
